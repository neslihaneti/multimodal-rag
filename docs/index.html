OVERVIEW

What this project demonstrates

Designed without heavy orchestration wrappers (<1,100 lines of modular core Python), every component is explicitly measurable, protected against untrusted document inputs, and validated on real scientific and technical PDFs.

indexer.py • file_processing.py

Adaptive Hybrid PDF Ingestion

Measures per-page largest object area (image_coverage via pypdfium2). Born-digital text and tables are extracted in seconds via Docling (text_layer), while scanned pages or pages with large diagrams (coverage ≥ 0.30) automatically route to Chandra OCR 2 (datalab-to/chandra-ocr-2).

db.py • PostgreSQL + pgvector

SQL-Native Hybrid Search (RRF) + Reranking

Combines 1024-dim BAAI/bge-m3 cosine similarity (HNSW index) with PostgreSQL TSVECTOR full-text search (GIN index) inside a single SQL CTE using Reciprocal Rank Fusion (k=60), then re-scores top-40 candidates with BAAI/bge-reranker-v2-m3.

rag.py • model.py

Agentic Multi-Hop Search & VLM Grounding

Rewrites conversational follow-ups into standalone queries, evaluates whether retrieved chunks are sufficient (ENOUGH vs. SEARCH: <new query> up to 3 rounds), and passes both text excerpts and rendered page PNGs to Qwen3-VL-4B-Instruct within a strict 9,000-token budget.

test_prompt_injection.py • evaluate.py

Defense-in-Depth & Hypothesis-Driven Phases

Protects against indirect prompt injection planted in PDFs (hidden white text & fake system notes) at both index time (regex canary/URL stripping on contextual summaries) and answer time. Every engineering change follows a strict Measure → Single Change → Re-Measure phase discipline.

ARCHITECTURE

End-to-end multimodal indexing & agentic retrieval pipeline

Models load lazily on Apple Silicon (mps) / CUDA with bfloat16 precision. Chandra OCR is automatically unloaded and GPU cache is cleared once indexing completes.

BENCHMARKS & ITERATIVE PHASES

Phase-by-phase engineering progression

Every improvement is isolated into a dedicated phase with dated Markdown/JSON reports committed under phases/faz-N/reports/. Final success is declared only on a separate, unseen holdout set.

Full Indexed Multimodal Corpus (3 Documents, 361 Pages, 1,164 Chunks)

  • doc1.pdf (ISTQB CT-AI Syllabus): 99 pages, 298 chunks (max 1,500 chars) — born-digital text layer, risk/acceptance tables, and ML workflow diagrams.
  • doc2.pdf (CODATA 2022 Fundamental Constants): 62 pages, 304 chunks — dense LaTeX equations and multi-page metrological tables with repeated table headers per split chunk.
  • doc3.pdf (1965 NASA Space Research Report): 200 full scanned pages, 562 chunks — 100% processed via Chandra OCR 2 covering optical, solar, radio/radar, X-ray/gamma-ray, and relativistic physics reports.
  • Unseen Final Holdout Set (eval/golden_final.jsonl): 72 stratified questions (10 factual, 10 paraphrase, 10 table, 9 figure, 8 multi-page, 10 Turkish, 15 unanswerable) held sealed until final evaluation.

Critical Engineering Discoveries & Fixes (Phases 1 → 6)

  • MPS Attention & Memory Guard (Phases 2 & J): PyTorch sdpa corrupted long multimodal prompts ("!!!"), while standard eager hit 50 GB memory spikes and segfaulted on long prompts. Built custom 1024-query blocked_eager attention + 9k token budget (fit_prompt) + 128-multiple padding (Z13).
  • Why HF no_repeat_ngram_size Silently Corrupts RAG (Phase 5b): Controlled sweeps proved decoder-only n-gram blocking penalizes prompt tokens too, forcing the model to mutate exact source numbers (2017 → 2020, 0.5 → 0.7 MeV). Repetition loops were eliminated instead via 1,500-char table re-chunking (Phase 5).
  • Stopword FTS & Bilingual Refusal Guardrail (Phases 4 & 5c): Stopword filtering + length-normalized ts_rank(..., 1) lifted keyword Recall@6 from 0.29 → 0.86; normalizing first-sentence refusals in rag.py eliminated refusal citation leaks (0.38 → 0.00) and enabled native Turkish refusals.
  • Visual Prefill Bottleneck (Phase 6a): Profiling revealed 3 page PNGs consumed ~3,500 prefill tokens (~66% of prompt); resizing max image side 1280 → 896px kept 22/22 figure/table accuracy while cutting p50 latency in the 24-question sweep from 32.3s → 20.9s.

ABLATION STUDY 01 • RETRIEVAL PIPELINE

Retrieval Ablation: Sparse FTS Fix → Hybrid RRF → Cross-Encoder

Removing English/Turkish stopwords and normalizing document length (ts_rank(..., 1) in Phase 4) lifted keyword Recall@1 from 0.07 → 0.51 (7.3×) and Recall@6 from 0.29 → 0.86 on the 69-question dev set.

ABLATION STUDY 02 • LATENCY vs. ACCURACY PARETO

Visual Token Prefill & Page Image Count Pareto Analysis

Downscaling page PNGs from 1280px → 896px halved visual prefill tokens. Reducing MAX_PAGE_IMAGES from 3 → 1 cut TTFT to 10.8s but regressed on 2 questions (q24, q29), choosing 2 images (17.8s p50, 0.97 dev accuracy) as Pareto-optimal.

FAILURE ANALYSIS & POST-MORTEMS

What failed during development & how we proved the root cause

Instead of cherry-picking only successful runs, every failed hypothesis or regression was isolated, root-caused with concrete question IDs, and either rolled back or solved at the architectural level.

POST-MORTEM 01 • PHASE 5b ROLLED BACK & FIXED IN CHUNKER

Why Hugging Face no_repeat_ngram_size Silently Corrupts RAG Facts

  • Symptom: On dense tables (q33, q36, q37, d2q10), the 4B VLM occasionally entered a sentence repetition loop.
  • Failed Hypothesis: Adding standard no_repeat_ngram_size=5 or repetition_penalty=1.05 during generation.
  • Root Cause Discovered: Controlled sweeps (phases/faz-5b/RAPOR.md) proved HF’s n-gram filter blocks n-grams appearing in the input prompt too. When a question and source excerpt shared a 5-gram, the model was forbidden from repeating the exact year or number, silently mutating 2017 → 2020 (q01) and 0.5 MeV → 0.7 MeV (d2q05).
  • Engineering Resolution: Rejected all decoding penalties. Eliminated loops at the root by splitting 6,104-char tables into ≤1,500-char chunks with repeated headers (Phase 5) and deduplicating identical sentences in the judge.
POST-MORTEM 02 • PHASES 2 & J (Z9–Z13) SOLVED VIA BLOCKED_EAGER

Multimodal Long-Context sdpa Collapse vs. 50 GB eager Memory Spikes

  • Symptom: On q43 (13.3k input tokens with 3 high-res page PNGs), standard eager attention caused an MPS segfault/OOM (spiking up to 50 GB memory footprint on d2q12).
  • Failed Hypothesis: Switching Qwen3-VL to PyTorch sdpa (Scaled Dot-Product Attention). Above ~9,500 multimodal tokens, sdpa silently overflowed and emitted "!!!!!!" garbage while corrupting subsequent calls in the same process.
  • Engineering Resolution: Implemented custom blocked_eager attention in attention.py (computing the Q • KT matrix in 1,024-query blocks), enforced a 9,000-token budget (rag.fit_prompt), and padded embeddings/reranker inputs to multiples of 128 (Z13) to stop MPS graph cache growth (cutting peak memory from 50 GB to ~9 GB).
POST-MORTEM 03 • PHASE 8 CAUGHT BY NON-REGRESSION GATE

Single-Image Context Starvation & TOC Loop on q29 and q24

  • Symptom: To push streaming TTFT under 10s, we tested reducing MAX_PAGE_IMAGES from 3 → 1. On the 22-question figure/table sweep (sweep8.json), 1 image scored a perfect 22/22 with 10.6s TTFT.
  • Full-Set Regression: On the full 82-question dev benchmark, 1 image achieved 10.8s TTFT and 0.93 raw faithfulness, but regressed on two questions (0.99 → 0.96): on q29, missing the second page image caused the VLM to loop over the Table of Contents and cite non-existent chunks [7][8]; on q24, it hallucinated "test cases or inputs".
  • Engineering Resolution: Enforced our strict non-regression rule (max 1 question drop allowed for speed) and selected MAX_PAGE_IMAGES = 2, which restores q29 while cutting TTFT from 17.7s to 12.9s and overall p50 latency from 19.9s to 17.8s.
POST-MORTEM 04 • PHASES 3b, 5c & 6a SOLVED IN PYTHON GUARDRAIL

Conditional Prompt Exceptions in 4B Models & Cross-Chunk Attribution Drift

  • Symptom 1 (Refusal Citations): Phase 3’s mandatory citation prompt reduced uncited answers from 0.30 → 0.00, but caused the model to append [1] to refusal sentences (0.38). Phase 3b’s prompt-only exception ("Cite every sentence EXCEPT when refusing") had zero effect (0.38 → 0.38).
  • Symptom 2 (Attribution Drift): Human audit of all 16 "unsupported" claims in Phase 6a revealed 7/16 were judge false negatives (facts were explicitly in the chunk, lifting true faithfulness to 0.95), while human inspection of the remainder showed most unsupported flags were accurate facts cited to adjacent page chunks.
  • Engineering Resolution: Moved conditional refusal logic out of the prompt into a deterministic 60-character streaming buffer in rag.py (is_refusal → clean bilingual refusal with 0.00 citations).

SYSTEM LIMITATIONS & HONEST OBSERVATIONS

Where the system currently falls short & open engineering challenges

True engineering maturity means acknowledging boundary conditions and failure modes transparently rather than claiming flawless production readiness.

1. Multilingual Performance Gap (Turkish vs. English)

On the final unseen holdout, Turkish retrieval remained robust at Recall@6 = 0.90, yet answer correctness dropped to 0.70 (vs. 0.95+ on English questions), isolating the primary bottleneck to generation rather than search.

  • Language-Drift in Generation (Resolved in Phase 9): The 4B VLM occasionally answered Turkish queries in English (e.g., f57). Phase 9 introduced deterministic answer_language() enforcement, reducing language mismatch to 0 with 89 passing tests.
  • Cross-Lingual Terminology Mismatch (Tested in Phase 10): Conceptual Turkish queries (e.g., "Kavram kayması nedir?") cannot match English passages without query translation. Phase 10 proved translation lifted dev correctness to 0.99 (12/12 Turkish correct), but added ~9s latency; rolled back to Phase 9 to respect TTFT limits. Phase 10 code preserved; single-pass reranking is the planned fix.
  • Inflectional Stemming Deficit: PostgreSQL full-text search uses the unstemmed simple dictionary, so inflected Turkish words rely on dense vector recall.
  • Failed Holdout Questions: f49 (flexibility vs. resilience nuance), f51 (over-cautious false refusal on valid passage), and f54 (omitted binding energy derivation).
  • Governance Artifacts: Full system reporting committed in docs/MODEL_CARD.md and risk self-assessment in docs/NIST_AI_RMF.md.

2. Hardware & Local VLM Constraints

Executing completely air-gapped on local unified memory entails physical trade-offs against multi-billion parameter cloud APIs:

  • Streaming TTFT (15.2s vs. 15s Target): Processing two 896px page images plus cross-encoder reranking incurs ≈4–5 s retrieval + ≈7–10 s prefill before the first generated token appears.
  • 4B Parameter Ceiling: 4B models struggle with complex compound instructions (e.g., f39 missed the specific bolometer instrument and f44 lost multi-page proton radius nuances).
  • Local Single-User Architecture: Current database connections and model memory footprints are optimized for a dedicated workstation, requiring batch queueing for multi-tenant deployment.
