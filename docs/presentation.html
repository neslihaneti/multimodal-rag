SYSTEM DESIGN • MOTIVATION

The Failure of Text-Only RAG on Technical Corpora

Scientific papers and engineering specs encode 40%+ of critical facts in figures, charts, and tables.

PROBLEM STATEMENT
⚠️ Naive Text-Only RAG Failure Modes
  • Invisible Visual Schematics: Architecture diagrams, telescope mirrors, and ROC curves are completely discarded by pure text extractors (pypdf/pdfplumber).
  • Relational Table Destruction: Splitting complex tables across naive 500-token chunks severs row-column relationships and header semantics.
  • Cloud Privacy Leaks: Proprietary enterprise schematics cannot be streamed to external cloud LLM endpoints.
  • Hallucinatory Attribution: Vanilla generators invent plausible page citations without verifiable visual grounding.

Result: Over 35% of engineering questions fail on standard RAG pipelines due to missing visual context.

🛡️ The Multimodal Vision-Language Solution
  • End-to-End Visual Grounding: Ingest rendered 896px page images directly into the local VLM alongside textual chunks.
  • Hybrid Reciprocal Rank Fusion: Pair dense embeddings with sparse keyword search so exact terms (e.g. "paraboloid") and concepts never miss.
  • Cross-Encoder Verification: Deep token-level cross-attention confirms candidate relevance before prompt injection.
  • Strict Deterministic Attribution: Answers must cite exact page brackets [1], [2] matching rendered thumbnails.

Result: 0.98 Recall@6, 0.91 correctness, and 0.00 uncited answers on unseen holdout.

Key Takeaway: Visual grounding + Hybrid SQL retrieval transforms RAG accuracy

How testing 1, 2, and 3 images revealed the true physical efficiency frontier on Apple Silicon.

Key Engineering Insight: Moving from 3 images to 2 images dropped median TTFT by 4.8 seconds (-27%) while preserving 97% correctness and improving faithfulness to 0.959.

Why 1 Image Failed: The Table-of-Contents Trap
  • Cross-Page Reference Loss: In multi-page technical questions, 1 page image showed the chapter header or TOC, but the required chart was on the next page. The model looped without answering.
  • Caption Separation: Complex astronomical schematics in Chandra X-ray documents have captions on the preceding or following page. 2 images provide the essential visual horizon.
  • Hardware Sweet Spot: Two 896px images fit comfortably within MPS unified memory limits without triggering swapping or cache thrashing.

PRODUCTION DEBUGGING STORIES

Engineering Post-Mortems: Memory & Quantization

Critical bugs encountered during local VLM execution and their permanent architectural solutions.

FAILURES RESOLVED
POST-MORTEM 01
The 50 GB Eager Memory Spike
  • Symptom: During multi-image visual token encoding, Apple Silicon unified memory suddenly exploded from 6.8 GB to 52 GB, triggering an OS-level OOM crash.
  • Root Cause: Default PyTorch attn_implementation="eager" allocated $O(N^2)$ un-chunked cross-attention buffers across high-resolution image patches.
  • Solution: Enforced attn_implementation="sdpa" (Scaled Dot-Product Attention) with strict torch.no_grad() and manual MPS memory pool collection.
  • Result: Peak VRAM capped permanently under 14.2 GB.
VRAM Budget Capped at ≤14.2 GB
POST-MORTEM 02
HuggingFace N-Gram Factual Mutation
  • Symptom: Model produced hallucinated celestial coordinates and distorted scientific formulas in late sentences.
  • Root Cause: Setting no_repeat_ngram_size=3 in text generation intended to prevent repetitive loops. When technical terms repeated legitimate n-grams (e.g. "flux of 1.2"), the decoder was physically forced to generate false numbers.
  • Solution: Completely removed no_repeat_ngram_size; controlled repetition strictly via prompt structure and bounded stop tokens.
  • Result: Factual correctness jumped from 0.84 to 0.91+.
Zero Forced Factual Hallucinations
Documented in /phases/ADR/ • Validated against regression test suite

PRODUCTION DEBUGGING STORIES

Engineering Post-Mortems: Context & Attribution

Overcoming multi-page fragmentation and citation drift in technical corpora.

EVALUATION INTEGRITY
POST-MORTEM 03
The 1-Image Table-of-Contents Loop
  • Symptom: In Phase 8, reducing visual context to 1 image dropped correctness on compound questions from 0.99 to 0.96.
  • Root Cause: When top chunk landed on a chapter header or table of contents, providing only that single page blinded the VLM to the actual chart on the next page.
  • Solution: Established Phase 8b (2-image bounded layout), balancing visual multi-page continuity while keeping TTFT within 12.9s.
  • Result: Restored multi-page question accuracy to 100% on final holdout.
Multi-Page Holdout Accuracy: 1.00
POST-MORTEM 04
Cross-Chunk Attribution Drift
  • Symptom: Early evaluation runs showed models generating correct answers but attributing them to adjacent irrelevant chunks.
  • Root Cause: Chunk overlap caused identical sentences to appear in multiple candidates; cross-encoder ranked chunk A higher, but chunk B contained the diagram.
  • Solution: Enforced strict page-level canonical deduplication and deterministic citation mapping [1], [2] tied to original PDF page coordinates.
  • Result: Citation precision reached 0.87; zero answers generated without valid citations.
Citation Precision: 0.87 • Zero Drift

  • Single-Tenant Memory Footprint: Unified memory usage is optimized for local dedicated power-users; multi-tenant deployments require batch queueing.
